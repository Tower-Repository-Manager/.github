
# Tower - Git Branch Review and Repository Management

> Examine branch relationships, review changesets, and organize repository history in a visual Git workspace.

Tower is a graphical Git client for developers who need a clear view of repository activity. Its interface brings working copy changes, commit history, branch navigation, and remote operations together for day-to-day source control tasks.

The application supports reviewing modifications, staging selected lines, comparing revisions, managing stashes, and working through merge conflicts. Branch review tools also help identify branches that may need attention before repository cleanup.

## Repository Management Features

| Feature | Description |
|---|---|
| Working Copy | Inspect modified, added, and deleted files before committing. |
| Commit History | Browse repository history and inspect changes associated with commits. |
| Branch Review | Compare branches against a selected base and examine their status. |
| Line Staging | Select specific lines or sections to include in a commit. |
| Visual Diff | Review file revisions and identify changes between versions. |
| Merge Conflict Handling | Examine conflicting changes and work toward a resolution. |
| Stash Management | Store temporary work and restore it when needed. |
| Interactive Rebase | Reorganize commit history using supported rebase operations. |
| Remote Operations | Fetch, pull, and push repository changes. |
| File History | Review changes associated with an individual file. |
| Pull Request Integration | Access supported pull request information from connected services. |
| Worktree Management | Work with linked working trees and their associated branches. |

## Exploring the Working Copy

![Tower Working Copy Interface](https://www.git-tower.com/assets/img/release-notes/windows/14/working-copy.png)

The Working Copy view provides a focused place to inspect pending modifications before creating a commit. Review individual files, compare changed content, and stage only the sections that belong in the next changeset.

This approach helps separate unrelated edits and makes each commit easier to understand later.

## Reviewing Branch Relationships

Tower's branch review tools make it possible to compare local branches against a selected base. Inspect ahead and behind counts, check merge status, and identify branches that may require cleanup.

Before deleting or integrating a branch, review its changes and confirm that the relevant work has been incorporated as intended.

## Preparing Changes for Integration

1. Open the repository and inspect its current working copy.
2. Review modified files and examine the relevant differences.
3. Stage the lines or files intended for the changeset.
4. Create a commit with a clear, descriptive message.
5. Compare the working branch with its intended base.
6. Review merge status before integrating changes or cleaning up branches.

These checks help keep repository history understandable and reduce uncertainty when several branches are active at once.
